# TillCount — Decisions

Where the handoff or Figma left a requirement open, TillCount takes the interpretation that
preserves data, stays offline and does not widen scope. Each decision is recorded here.
Owner-level commercial decisions are in `OWNER_DECISIONS.md`; dependency choices in
`DEPENDENCY_DECISIONS.md`.

| ID | Decision | Why |
|---|---|---|
| D-01 | Secure random comes from `globalThis.crypto.getRandomValues`, else `expo-crypto`. `Math.random` is never used for ids, salts or nonces. | Hermes has no Web Crypto. A backup salt or nonce from a weak source would weaken encryption without any visible failure. See `DEPENDENCY_DECISIONS.md` D-01. |
| D-02 | Every barcode goes through one path: `normalizeBarcode()` in `src/domain/barcode.ts`. Scanner, manual entry, product form, CSV import, family transfer and restore all call it. UPC-E is expanded to UPC-A and UPC-A to EAN-13 (leading 0) before comparison. | Handoff requires one normalisation path. Without it the same can would count as two products. |
| D-03 | The app says "last counted quantity" and never says "stock", "live stock" or "on hand". The locale-quality test fails any string that does. | Non-negotiable: TillCount does not know sales between counts. |
| D-04 | Archiving a product keeps its barcodes and SKU. Unarchiving is refused, with an explanation, when one of those codes now belongs to another active product. The user must remove the clash first. | Silently moving a barcode would change what future scans count, and the user would not see it. |
| D-05 | Skipped / not-counted products keep their previous snapshot. Completing a count writes snapshots only for products that have an entry in that count. | Non-negotiable: skipped products are never set to zero. |
| D-06 | A completed count is immutable. It cannot be edited, reopened or deleted. A correction is a new count. The count's attention list (`attentionAtCompletion`) is frozen at completion, so history shows what needed ordering at the time. | Non-negotiable: completed history is immutable. |
| D-07 | `Product.caseQuantity` / `packQuantity` hold the base units per case / pack when no case or pack barcode carries that number. Case + loose entry uses them first, then barcode quantities. | Figma's Quick quantity has Case / Pack / Loose. Many shops have no case barcode, so the number needs a home. |
| D-08 | Only one open count at a time. Starting another count asks Keep / Discard. The open count is saved after every change (coalesced writes) and survives an app kill. | Two parallel counts could write conflicting snapshots for the same product. |
| D-09 | "Finish count" is idempotent. A double tap or a re-entry shares one completion promise. The count header, entries and snapshots are written in one storage transaction. | Stops duplicate history rows and half-applied counts. |
| D-10 | Storage is crash-safe. Collections are written as generation-numbered chunks behind a manifest, and multi-key writes go through a transaction journal that is finished or rolled back at start-up. Reads fail closed: unreadable data shows a recovery screen and keeps a `:corrupt:` copy. The app never renders empty data over real data. | No hidden data loss (non-negotiable). AsyncStorage has no multi-key atomicity. |
| D-11 | A data file from a newer app version (`schemaVersion` > current) is refused, not downgraded. | A downgrade could drop fields the newer version relies on. |
| D-12 | CSV import never overwrites silently. Rows that match an existing product (by barcode, then SKU) are shown as "matched". Updating them is an explicit toggle on Import review, and it is **off by default**. Duplicates within the file are flagged. | Non-negotiable: no silent CSV overwrite. |
| D-13 | Keyboard handling uses `react-native-keyboard-controller` through `AppKeyboardScrollView` / `AppKeyboardBottomSheet`. Screens do not add their own keyboard offsets. | Carried over from the donor: one proven keyboard path. |
| D-14 | The PDF previews (Count PDF, Reorder PDF) are a native page-mock card, as drawn in Figma. The real A4 PDF is rendered with `expo-print` when the user shares it. There is no in-app PDF viewer. | The Figma frames are page mocks. A PDF viewer needed three native modules (pdfium, blob-util, webview) that add size and attack surface. |
| D-15 | Backup and restore are **never** gated by Free/Pro. Figma lists "Backup" among Pro benefits, so this is raised as owner decision OD-05. Until it is decided, users can always get their data out and back in. | Choosing the data-preserving reading: a paywall must never stand between a user and their own data. |
| D-16 | Restore replaces all operational data in one journaled step. It checks integrity before and after the write, and rolls back if either check fails. Device-local keys (language, error log, restore journal) are never part of a backup. | Restore is the one flow that deletes data by design, so it must be all-or-nothing. |
| D-17 | Backup files are named `TillCount_Backup_YYYYMMDD_HHMM.tcb`. They are AES-256-GCM with a scrypt key (N=2^15, r=8, p=1) and a passphrase of at least 8 characters. A lost passphrase cannot be recovered, and the Create backup screen says so. | Handoff naming rule and encryption requirement. |
| D-18 | Screens reachable only from Figma overflow menus (Currency, Count history, Favourite counts, Categories, Suppliers, Locations) sit in the More overflow menu and in the rows that naturally lead to them. Choose location opens Count setup directly. | Figma draws these screens with no visible entry point. Every one of the 71 must be reachable (the route-map test proves it). |
| D-19 | "Remove from reorder alerts" (Edit reorder target) clears the product's reorder level and target stock. The product, its counts and its history stay; it simply no longer raises a low-stock alert or a suggested order. | Matches Figma's wording without adding a hidden per-product flag. |
| D-20 | Settings load tolerantly: unknown or invalid fields fall back to defaults field by field, and valid fields are kept. | A settings problem must never block access to counts and products. |
| D-21 | Sample data loads only into an empty app. Every sample record is marked `isSample`. "Remove sample data" in Data & backup deletes only records marked `isSample`. | A demo catalogue must never mix silently with a shop's real products. |
| D-22 | Arabic text: all app text goes through `src/ui/Text`, which starts each string with a right-to-left mark in RTL. Numbers and quantities are wrapped in left-to-right marks (`ltr()`). | Android aligns default-aligned text by its first strong character, so "Coca-Cola 500ml" would otherwise sit on the left of an RTL row. The lint rule forbids importing `Text` from `react-native`. |
| D-23 | Screenshots in `artifacts/screenshots` come from a web-only harness (`index.web.js` → `tools/screenshots/Harness.tsx`) that renders the real screens with react-native-web in Chromium. They show layout, copy and RTL, not device pixels. The Android bundle never includes the harness. | No emulator can run in the build container (no KVM). Device screenshots are listed as HUMAN REVIEW in the final handover. |
| D-24 | Icons are Ionicons (`@expo/vector-icons`), picked as the closest match to each Figma icon. | Figma asset downloads are blocked from the build environment, and Ionicons ships inside Expo. |
| D-25 | Reorder formula (`src/domain/reorderEngine.ts`, the only place it is computed): status is not-counted / out (0) / low (≤ reorder level) / ok; suggested order = max(0, target stock − last counted quantity), kept at 3-decimal precision for measured units. Products with no target are listed as "needs setup" (or hidden, per Reorder settings). There is no forecasting and no case rounding. | Handoff reorder formula. Figma copy: "no forecast". |
| D-26 | Action buttons sit directly under the screen content, as in Figma. Only screens whose body is a virtualised list (Review, List count, Import review, etc.) pin their buttons under the list. | Figma is authoritative for layout. Lists can be thousands of rows long, so their actions must stay reachable. |
| D-27 | The PDF page mock shows up to 11 product rows, then "…and N more lines in the PDF". The printed PDF always has every row. | A fixed-size page card must not clip a row in half. |
| D-28 | Choose location opens with the first location that has products already selected, and lists locations in the order the shop created them (its walking order). Categories and suppliers stay A–Z with nothing preselected. | Matches Figma (Front shop selected, walking order). |
| D-29 | Import review rows and Restore preview summary rows have no chevron, because they open nothing. Figma draws chevrons on them. | A chevron that does nothing misleads. Row detail is already shown inline. |
| D-30 | Dates: English short months come from the app's own month list ("24 Sep 2026", as in Figma), not ICU's en-GB data, which says "Sept" and differs between Android versions. Legal "last updated" dates are shown in the reader's language. | Stable output on every device. |
| D-31 | The Pro feature list names "Till-family product transfer" in the fifth place, where Figma has "Encrypted backup and restore", because backup stays free (D-15 / OD-05). | Keeps the paywall copy true to what the app does. |
| D-32 | "−" on a product that is not counted yet does nothing. A 0 is recorded only by typing 0 or stepping down from a counted value. | One stray tap must not mark a product as counted at 0, because it would show as out of stock on the Reorder list. |
| D-33 | The camera's duplicate window restarts on every sighting of the same code, so a code held in view counts once. It counts again only after it has been out of view for 1.5 s. Scanning pauses while the out-of-scope question is open. | Stops a held can from adding +1 every 1.5 s. |
| D-34 | The Free product cap counts every real product still in the catalogue, archived included. Archiving does not free a slot, restoring stays free, and deleting frees a slot. | Otherwise archive, create and restore would get past the cap, and blocking restore would lock the user's own data. |
| D-35 | An 8-digit code typed by hand also matches its UPC-E expansion (what the camera reports for the same label). | Stops the same physical code being given to two products. |
